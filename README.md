# Bids AI — Document Intelligence Showcase

Upload a bid solicitation, watch it get parsed, matched against the item catalog and bid/purchase
history, priced, and turned into a proposal — live. FastAPI + React on Databricks Apps, Lakebase as
the transactional store with Unity Catalog reference tables synced in for fast reads, and a
Databricks Asset Bundle for deployment.

See `NARRATIVE.md` for the live demo script. Completed plans, design handoffs, and
sales notes live under `docs/archive/` — see `docs/README.md`.

## One-time setup (FEVM workspace)

```bash
databricks auth login --host https://fevm-pavan-naidu.cloud.databricks.com --profile FEVM

# 1. Create the Lakebase Postgres database (one-time; app creates its own tables on first boot)
DATABRICKS_CONFIG_PROFILE=FEVM python3 src/bootstrap/setup_lakebase.py \
    --instance dbdemosonlinestorepavannaidu --database bids_ai

# 2. Deploy the bundle (schema/volume/app/jobs/synced-tables resources)
databricks bundle deploy -t dev --profile FEVM

# 3. Seed the synthetic catalog, historical bids, purchase history, and sample bid documents
databricks bundle run seed_demo_data -t dev --profile FEVM

# 4. Deploy again now that the source tables exist, so the Lakebase-synced tables can be created
databricks bundle deploy -t dev --profile FEVM

# 5. Build the Vector Search endpoint + index over the item catalog
databricks bundle run build_vector_search_index -t dev --profile FEVM

# 6. Grant the app's service principal access (Unity Catalog + Postgres-side on the synced schema)
databricks bundle run grant_app_access -t dev --profile FEVM

# 7. Build the React frontend into the app's static/ dir, then deploy the app's code
cd src/web && npm install && npm run build && cd ../..
databricks apps start bids-ai-demo-dev --profile FEVM
databricks bundle run bids_demo_app -t dev --profile FEVM
```

Step 6's Postgres grant runs as a Databricks Job by default; if that job OOMs loading psycopg's C
extension (a known flakiness in the serverless job environment), run the grant locally instead —
see the `_grant_postgres_ref_access` function in `src/bootstrap/grant_app_access.py` for the
equivalent logic to run with `DATABRICKS_CONFIG_PROFILE=FEVM python3`.

## Sample bid PDFs for live demo upload

`sample_bids/` holds real, downloaded PDF files (not just Volume-only samples) you can
drag-and-drop straight into the app during a live demo without depending on the "Load a
sample" button: one VA Medical Center solicitation plus five more government bid letters
(DLA Troop Support, Bureau of Prisons, Arizona DOC, City of Baltimore Health Dept., Indian
Health Service) with randomized item mixes/quantities/due dates, generated by
`_build_government_bid_documents()` in `src/shared/bids_demo/sample_documents.py`
(fixed seed `20260714`, reproducible). These same 5 are also written to the Volume by
`seed_demo_data` and appear in the in-app "Load a sample" picker.

## Repo layout

- `databricks.yml`, `resources/` — the Databricks Asset Bundle (schema, volume, app, jobs, Lakebase-synced tables)
- `src/shared/bids_demo/` — synthetic data + sample bid document generation, used by the bootstrap jobs
- `src/bootstrap/` — one-time setup scripts, run as Databricks Jobs (seed data, build the Vector Search index, grant access)
- `src/app/` — the Databricks App: FastAPI backend (`server/`) serving the built React app (`static/`)
- `src/web/` — React (Vite + TypeScript) frontend source
- `dashboard/` — the Lakeview dashboard build script + exported definition
- `NARRATIVE.md` — live demo script
- `docs/` — living index plus `docs/archive/` for historical plans and handoffs

## Local backend dev

Without Lakebase env vars set, the app falls back to an in-memory store and in-process synthetic
reference data (`server/state.py`, `server/reference.py`) — useful for iterating on the API/frontend
without a live workspace. Document parsing/matching still calls out to the configured Databricks SQL
Warehouse and Vector Search endpoint, so those need a valid `DATABRICKS_CONFIG_PROFILE`.

Catalog matching defaults to Databricks hybrid keyword-similarity retrieval. Set
`BIDS_SEARCH_MODE=ann` on the app as a rollback switch to use ANN-only retrieval.
